# 코딩 스타일 (General)

> **General** — 회사·도메인 무관, 어느 프로젝트에도 재사용 가능.
> 출처: SEEMEDI `STD-CODE-0001` 코딩컨벤션 가이드에서 회사 특이 부분 제거.
> 언어별 상세: [../by-language/](../by-language/)

## 대원칙

1. **가독성 우선** — 코드는 작성보다 읽히는 횟수가 많다. 영리함보다 명료함.
2. **자동화 우선** — 스타일 논쟁은 포매터에 위임. 리뷰에서 스타일을 지적하지 말고 도구가 잡게 한다.
3. **일관성 우선** — 지역 관례가 전사 규약과 충돌하면 전사 규약. 기존 파일 수정 시 그 파일의 지배적 스타일 존중.

## 파일 공통 규약 (전 언어 MUST)

| 항목 | 규칙 |
|------|------|
| 인코딩 | **UTF-8** (BOM 없음) |
| 개행 | **LF** (`\n`). CRLF 금지. `.gitattributes`로 정규화 |
| 파일 끝 | 최종 개행 1개 포함, 후행 공백 제거 |
| 들여쓰기 | **스페이스** (탭 금지). 폭은 언어별 |
| 최대 줄길이 | 언어별: Python 88 · TypeScript 80 · Kotlin/Swift/C++ 100 (주석·URL 불가피 시 예외) |
| 빈 줄 | 연속 빈 줄 최대 1개, 파일 시작·끝 빈 줄 금지 |

## 문서화 주석

- **공개(public) API는 문서화 주석 필수.** 각 언어 표준 포맷 사용(KDoc/docstring/TSDoc/Doxygen/Swift Markup).
- 문서화 주석은 **무엇을·왜**를 설명. **어떻게**(구현)는 본문 주석·코드로.
- 자명한 게터/세터·오버라이드에는 강제하지 않음. 시그니처로 드러나는 정보 반복 금지.

## 주석 언어 정책

| 대상 | 언어 |
|------|------|
| 공개 API 문서화 주석 | **영어** (MUST) |
| 공개 식별자·에러 메시지 키 | 영어 (MUST) |
| 내부 구현 주석(비공개) | 팀 언어 허용 (MAY) |

## 태그 주석 (TODO/FIXME)

작업 추적 표식은 **책임자와 추적 링크**를 포함한다. 형식: `TODO(작성자, 이슈참조): 설명`

| 태그 | 의미 | 이슈참조 |
|------|------|:---:|
| `TODO` | 향후 개선/추가 | 필수 |
| `FIXME` | 알려진 결함·회피책 | 필수 |
| `HACK` | 의도적 임시 우회(부채 명시) | 필수 |
| `NOTE` | 참고 설명(조치 불요) | 불요 |
| `XXX` | 주의 요망 | 불요 |
| `DEBUG` | 디버깅용 임시(커밋 전 제거) | 불요 |

- **이슈참조 없는 TODO/FIXME 금지** — 추적 불가한 부채 방지.
- `DEBUG` 표식·디버그 코드는 **커밋·머지 전 제거**.
