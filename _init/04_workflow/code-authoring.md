# 04 · 작업 방식 — 코드 작성

> ⚠️ **최고 규칙(_init) — 일반 task 중 변경 금지.** 개정은 명시적 승인으로만.
> 상위: [../04_workflow.md](../04_workflow.md) W1~W3 공통 게이트를 먼저 따른다.

코드를 생성·수정·리팩토링·삭제하는 작업의 워크플로우.

## CA1. 컨벤션 적용

- **General 컨벤션은 항상** 적용한다 — `code-conventions/general/`(by-task·by-language).
- **조직 레포이면 그 조직 정책을 추가** 적용한다 — 예: SEEMEDI 레포는 `code-conventions/seemedi/`. 조직 판별·우선순위는 [../02_classification.md](../02_classification.md)·[../01_precedence.md](../01_precedence.md) P4.

## CA2. 승인 게이트 (코드)

- 대량 변경·구조 변경·파일 삭제·인터페이스 변경은 **먼저 제안하고 승인** 후 실행(W1).
- 소규모 국소 수정은 바로 진행하되 결과를 보고한다.

## CA3. 품질·안전

- 기존 파일 수정 시 그 파일의 지배적 스타일을 존중한다.
- 시크릿·자격증명을 코드/로그에 남기지 않는다. 조직 특이 민감정보(예: SEEMEDI PHI)는 조직 정책이 강화한다.
- 테스트·게이트가 있으면 통과를 확인하고, 실패는 사실대로 보고한다(W3).

## CA4. 커밋·푸시

- 커밋/푸시는 사용자가 요청할 때만 한다. 외부로 나가는 작업(푸시)은 사전 확인(W3).
